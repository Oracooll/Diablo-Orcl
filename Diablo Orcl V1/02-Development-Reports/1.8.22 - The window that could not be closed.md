# 1.8.22 - The window that could not be closed

## The report

> "This new UI gave me an idea because of a bug it introduced - as a hard game-wide ui rule we
> should put small red X buttons at top right corner of all possible windows the users is facing
> browsing the ui. This button should be a CLOSE WINDOW button clickable with mouse. As you can
> guess the bug i am talking about is that i found no way of closing Levski UI other than quit to
> main menu."

The bug is real and the diagnosis is exact. Levski's Roar is the first window in the game that is
neither docked to a panel nor opened from a button that also closes it. `ToggleLevskiRoar()` is
reachable only from `OperateObject`'s `OBJ_STAND` case - so the only way to close the window was to
click the monument again, and the monument is underneath the centred window. `CheckLevskiRoarClick`
returns `true` for every point inside the panel, header and padding included, so the click that
would have re-toggled it was absorbed by the thing it was meant to close. Escape did not help
either: `PressEscKey` walks a list of known flags and this window was not on it.

## The rule, not the patch

Patching Levski's Roar alone would have left the next free-floating window to rediscover the same
hole. The fix is a shared module - `Source/oracool/window_close.{h,cpp}` - with three functions and
no knowledge of any particular window:

| Function | What it does |
|---|---|
| `GetWindowCloseButtonRect(window)` | 18x18, inset into the top-right corner by `OrnateBorderWidth` |
| `DrawWindowCloseButton(out, window)` | dark red plate, lighter outline, a two-pixel-thick red X |
| `CheckWindowCloseButtonClick(window, mouse)` | hit test only - the caller decides what closing means |

The X itself is drawn as a stack of short horizontal runs, one per row, because the engine has no
diagonal-line primitive; the run length is also what gives each stroke its thickness.

## Where it is wired

Two call sites cover eight windows, because the routing they hook into was already centralised:

- **The left panel** - Character, Quest log, Stash, Waypoints, Crafting. Drawn once after the
  `GetLeftPanelContent()` switch in `scrollrt.cpp`, hit-tested once before that same switch in
  `diablo.cpp`. Closing goes through a new `CloseLeftPanelContent()` in `control.cpp`, which sits
  directly beside `GetLeftPanelContentRect()` for the reason that function exists: five windows
  share one slot, and five hand-written closers would drift apart the way the draw and click chains
  once did. The Stash branch calls `CloseStash()` rather than clearing `IsStashOpen`, since the
  former also returns a held item and releases the chest object.
- **The right side** - Inventory (`CloseInventory()`) and the Abilities window (`sbookflag`).
- **Levski's Roar and its recipe book** - each carries its own X, and the book's X closes the book
  rather than the window under it. The window's X is tested *before* the Transmute and Recipes
  buttons and before the grid, so nothing can shadow it.

Escape now also closes Levski's Roar, added to `PressEscKey` beside the burger menu - the keyboard
half of the same rule.

## What is deliberately not covered

The burger menu is a popup, not a browsable window: it already closes on Escape and on a click
outside itself, and an X on a six-icon strip would be larger than the icons. The gold-split and
gold-withdraw prompts are modal dialogs with their own Cancel. If either of those reads wrong in
play they are one call each to bring in.

One behaviour survives the new button by design: with a full backpack, `CloseLevskiRoar()` still
refuses and logs *"Your pack is full - Levski's Roar keeps what it holds."* The grid is not save
state, so closing on a full pack would destroy whatever is in it. The X is now the normal way out;
it is not a way to lose items.

A note for future runs: a `-j4` ctest showed a third failure,
`LoadSaveOracoolItemExtensionsTest.RoundTripsTieredItemStoredInExtraTab`, which passes in isolation
and passes in a serial run. It is parallel interference between tests sharing a save path, not a
regression - but it will keep reappearing under `-j`, so the suite is worth running serially before
believing a third failure.

## To look at in game

1. Open the inventory, the character sheet, the stash, the quest log, the waypoint list and the
   Abilities window in turn - each should wear a red X at its top-right, and each X should close
   only its own window.
2. Click the monument, then click the X. The window closes. Press Escape instead - it also closes.
3. Open the recipe book and click *its* X - the book closes, the window stays.
