# 1.8.32 - Gold reaches the bottom three rows

First of the Small batch.

`AddGoldToInventory`'s two placement loops were written for the vanilla **10x4** backpack:

```cpp
for (int i = 39; i >= 30 && value > 0; i--)        // "last row", right to left
for (int x = 9; x >= 0; x--) for (int y = 2; y >= 0; y--)   // the three rows above
```

The grid has been **10x7** since the inventory rebuild. Cells 40-69 were unreachable, so gold could
never be auto-placed below the fourth row however full the rest was.

This is the stash's "last 6 rows" bug of 2026-08-16 in a different file - a literal that did not grow
when its grid did. Both loops now derive from `InventorySizeInSlots` and `InventoryGridCells`, so the
next resize follows on its own.

**Vanilla's fill order is preserved deliberately.** Bottom row first, right to left, then the rest in
columns from the bottom up and the right across - gold collects in the corner furthest from where
items land, instead of fragmenting the space they need. That reads as intentional to a player and it
would have been easy to lose while fixing the bounds.

Covered by `AddGoldToInventory_UsesTheWholeSevenRowGrid`, which blocks the first four rows entirely
and asserts the gold still places. The test runs in multiplayer, because single-player sends
picked-up gold straight to the stash pool via `GoldAutoPlace` and never reaches these loops - which
is also why the bug survived: the path is only live in the mode this fork does not ship.
