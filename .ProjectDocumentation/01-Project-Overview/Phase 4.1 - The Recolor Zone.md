# Phase 4.1 — The Recolor Zone

The megaplan's Phase 4.1: *"Zone 1 as pipeline proof: a recolor zone. Exactly Hellfire's own trick
(Crypt = recolored Cathedral): new palette + retinted tileset + new roster + new waypoints +
entrance. Validates every tool with zero AI-art risk."*

This is the plan, written **after** establishing the engineering facts rather than before, because
the interesting ones turned out to be non-obvious.

## The zone

**The Sunless Vault**, levels 25-28, generated by the Cathedral's own generator under a cold,
darkened palette. Cathedral rather than Crypt because the Crypt is already Hellfire's recolor of it
and reusing the same generator a third time proves the mechanism without competing with either.

## Step 1 — the palette (SHIPPED, v1.7.27)

`levels/l1data/sunless_1.pal`, produced by the committed `tools/PaletteVariant.ps1` from vanilla's
`l1_1.pal`: pulled 42% toward steel blue and darkened to 88%.

Verified rather than assumed:

- **768 bytes**, the format the loader requires.
- **731 of 768 bytes changed** — a real recolor, not a rounding error.
- **Indices 152-159 byte-identical to the source.** These are `PAL8_GREEN`, the mini-ramp this fork
  overwrites with its injected forest green. A variant that touched them would fight `LoadPalette`
  every frame. The tool skips them by design; this confirms it actually does.
- **Index 0 preserved**, the transparency convention.
- **It ships automatically.** `tools/build_oracool_mpq.cmd` globs the whole asset tree, so the file
  packed as `levels\l1data\sunless_1.pal` with no manifest edit — 78 files now, up from 77.

The before/after swatch grid is unmistakable: the same palette structure, cold and dim instead of
warm and lit. That is the Crypt trick, and the tool is now proven on real vanilla data rather than
on its own test fixture.

## The facts that shape steps 2-5

These took real digging and they change the order of the work.

**`NUMLEVELS` is 25 and it is a compile-time array bound**, not just a loop limit —
`Player::_pLvlVisited[NUMLEVELS]`, `_pSLvlVisited[NUMLEVELS]`, `glSeedTbl[NUMLEVELS]` and four
debug seed tables are all sized by it. A four-level zone needs 29.

**That is NOT a hero-file break.** `_pLvlVisited` is written by `loadsave.cpp`'s
`SavePlayer`/`LoadPlayer` — the *game* save — and is absent from `pack.cpp`'s `PlayerPack`, which is
what the hero file carries. V1 always starts a New Game, so the game-save layout moving costs
nothing, and the golden hero hash should not move at all. **This must be re-verified when the change
is made**, because "the hero hash did not move" is the whole claim.

**`giNumberOfLevels` is the runtime twin** (`gbIsHellfire ? 25 : 17`, set in `diablo.cpp` and again
in `loadsave.cpp`) and drives the save loops. It has to move with `NUMLEVELS`, in both places.

**`glSeedTbl` needs no work** — `multi.cpp` already seeds it with a `NUMLEVELS` loop.

**Level 24 is not a clean edge.** `currlevel == 24` is special-cased in at least six places
(monster.cpp twice, objects.cpp twice, msg.cpp, diablo.cpp) for Na-Krul and the Crypt's finale.
Level 25 must not inherit any of it, and the entrance from 24 has to coexist with the Na-Krul
sequence rather than replace it.

## Steps 2-5

**2. The level count.** `NUMLEVELS` → 29, `giNumberOfLevels` → 29 under Hellfire, plus the zone row
`{ 25, 28, DTYPE_CATHEDRAL, "The Sunless Vault", "levels\\l1data\\sunless_1.pal" }`. Verify the
golden hero hash is unchanged; verify every level 0-28 resolves to a zone.

**3. The entrance.** A stairway on level 24 that does not disturb the Na-Krul special cases. This is
the step to do with the user present — it is the one that changes an existing floor.

**4. Waypoints.** `MaxWaypointSlots` is already 64 and only 25 are used, so four more are additive.
The icons come from the same vault sheet the existing 25 were cut from.

**5. The roster.** Phase 3's monster variants, which is also what finally unblocks **Phase 3.1**
("TRN recolor variants wired into zone rosters") — that phase has been waiting on this zone existing
to have a roster to wire into. Note the prerequisite found during 3.2: `DrawMonster` only consults
`uniqueMonsterTRN` for uniques, so ordinary-monster recolours need that condition widened first.

## Why it stopped after step 1

Steps 2 and 3 change the global level count and an existing floor, and neither is verifiable without
playing. The crash reported at v1.7.20 is the argument: a change to shared level machinery, shipped
untested-in-play at the end of a long unattended run, is how a session ends with a screenshot rather
than a build. The palette had no such exposure — it is a new file nothing reads yet.
