# Audit of v1.9.43–1.9.46 (v1.9.47)

Everything since the external audit's response closed: the aura ground renderer (1.9.43), its two
geometry fixes (1.9.44), the Passive Skills page (1.9.45) and the passive slot system (1.9.46).
Reviewed adversarially — the question asked of each change was "how would I attack this if I hadn't
written it", not "does it look right".

Four findings. Three fixed, one recorded.

---

## P1 — `spell_book.cpp` was silently converted from CRLF to LF

**The whole file**, 1,581 lines of it, in the 1.9.46 commit.

This project's own notes carry a standing rule about exactly this: *never `perl -0pi` here; `perl -i`
and `sed -i` strip CRs*. I avoided all three and then did it with `awk`, which the rule does not
name. The check I ran beforehand reported "0 CR lines" and I believed it; the check was wrong, and
the diff was the thing that told the truth — 3,403 changed lines against 267 real ones.

Consequences: `git blame` for the file points at the wrong commit for every line, the commit's diff
is thirteen times its actual size, and the file no longer matches the repository's convention.

**Fixed.** Restored to CRLF; content verified byte-identical (`git diff --ignore-cr-at-eol` against
HEAD is empty), and the diff against the pre-audit baseline is back to its true 254 insertions /
13 deletions.

Worth generalising: the rule should be "never rewrite a whole file with a line-oriented tool", not a
list of three tool names. Checking the diff SIZE after any scripted edit would have caught this
immediately, and cost nothing.

## P1 — a locked passive refused in silence

`ClassTreeLockReason` answered from the skill's **tier**. A Passive Skills row is not gated by its
tier — it is gated by its own even-level requirement — so the function's test
`player._pLevel < tierLevel` was asking the wrong question, and when it came out false it fell
through and returned an **empty string**.

That is the precise failure the function was written to prevent. From its own header: a locked row
"used to refuse SILENTLY … The cell looked clickable and said nothing when clicked."

Not a corner case. A tier-0 passive has a tier level of 1 and a real requirement of 2, so it was
silent for **every** locked passive in the first row, at every level, and for every other passive in
the window between its tier level and its actual requirement.

Latent today — the click path answers with its own message before reaching this function — but it is
a public function returning a wrong answer, and the next caller would have inherited the bug.

**Fixed**, and verified by reintroducing it: with the passive branch disabled the new test reports
*"Heavenly Strength was silent at level 1"*, *"Vigilant was silent at level 5"*, and others.

## P2 — a filled slot could not tell you what was in it

Every passive draws an **empty plate**, because the icon art deliberately does not exist yet. So a
filled slot and an empty one differed only by plate tint, and nothing anywhere in the window named
which four passives a character was actually running.

That matters more than usual here because the user asked specifically for the slotting to be
user-friendly, and because it is the one piece of state the whole feature exists to express.

**Fixed.** Hovering a slot now names it, describes what it holds, and says how to empty it; a locked
slot gives its level; an empty open slot says what to do with it.

## P3 — recorded, not fixed: the aura blit's per-pixel cost

`BlitAura` walks the destination rectangle — 724×362 = 262,000 pixels at the eight-tile cap — and
performs roughly five integer divisions per pixel. The ring grew ~2× in area at 1.9.44, so this
doubled *after* the only build anyone has played.

The clearly-safe half is **fixed**: the loop was clipped to the visible range once instead of
testing and skipping each pixel individually. That transformation is provably equivalent — the
iterations removed are exactly the ones whose only action was `continue`.

The divisions are left alone deliberately. Removing them (a precomputed column table, unsigned
shifts for the power-of-two cases) is a rewrite of a renderer whose only verification is a
screenshot, and this file has already produced two silent geometry bugs. Not worth doing blind. If
the auras cost visible frame rate in play, that is the thread to pull.

## Checked and found sound

Recorded because "we looked" is worth as much as "we found":

- **`_pPassiveSlots` defaults.** The empty sentinel is `0xFF`, so a zeroed `Player` would read as
  "passive 0 in all four slots". No whole-struct `memset` exists; every reset path is `player = {}`,
  which applies the default member initialisers. A pre-1.9.46 hero has no chunk at all, so nothing
  writes the array — it must default correctly on its own. Now pinned by a test rather than by
  reasoning.
- **Zero-size rectangles.** The passive page returns an empty `TreeBarRect`. `Rectangle::contains`
  uses a strict upper bound, so it can never match — including at the origin.
- **The v1.9.44 projection.** Re-derived independently from the render walk (`Direction::East`
  advances screen x by `TILE_WIDTH`, so the tile mapping is `(32(x−y), 16(x+y))`). Semi-axes of
  `R·32·√2` and `R·16·√2` confirmed, and the ellipse confirmed tangent to the Chebyshev field's
  screen diamond — inscribed, so it never claims range the aura does not have.
- **`DrawAuraGround` call frequency.** Once per frame in `DrawGame`, not once per tile. It also
  lands before `ZoomScale`, so the ring scales with the world rather than fighting it.
- **Save-slot collisions.** The passives occupy class-relative slots that were unused in every class
  before 1.9.45 (Paladin 31+, others 30+ or 21+), so no existing character's investment data is
  reinterpreted.
- **Index-space bounds.** A class-relative index cannot reach the `0xFF` sentinel at 64 skills per
  class; now a `static_assert` rather than a fact that happens to hold.

## Verification

535/537, the two standing baseline failures. Three tests added, one of them verified by
reintroducing the bug it guards.

Still unverified, and unchanged by this audit: nothing from v1.9.43 onward has been seen running
except the auras themselves.
