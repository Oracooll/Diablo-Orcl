## Audit tracks

Put each track in its own report. Look in each track's listed files first. Follow any caller or callee you need.

### 1. Saves and state that outlives a game (highest priority)

Files: `pack.h/.cpp` (PlayerPack), `loadsave.cpp` (`OracoolItemFormatVersion`, currently 13), `pfile.cpp`, `oracool/imbuement`, `oracool/rift`, `oracool/companion`, `oracool/minions`, `oracool/rage`, `oracool/skill_points`, `oracool/auto_save`, `oracool/save_status`.

- **State that carries over between games.** Find any per-game state kept in a file-local `static` or in a namespace global that is not reset when a new game starts or another hero loads. This has caused real bugs before: state from one hero reached the next.
- **Saving and loading.** Every new per-hero field must be written and read back symmetrically. Check bounds when reading, and make sure a bad or short file fails in a controlled way, not by overrunning memory.
- **Summons and companions.** Check their golem slots 1-3, their timed life, their state when you change level or go to town, and what happens when a monster slot is reused.
- **Rift state.** Check what happens when a hero leaves a rift, returns to town, dies inside one, or saves while one is open.

### 2. The skill system

Files: `oracool/class_tree` (THE skill system for all six classes), `skill_facts`, `spell_ranks`, `rfa12_actives`, `rfa12_effects`, `passives`, `aura_field`, `aura_ground`, `curses`, `cold`, `warcries`, `melee_skills`, `paladin_*`, `rogue_arrows`, `necro_summoning`, `companion`, `rage`, `spell_timers`, `readied_spells`, `skill_picker`, `skill_sounds`, `weapon_throw`, `furious_charge`, `venom`, `chill`.

- **Rank bounds.** SpellID is an int16 and `MAX_SPELLS` has grown several times, so check every array indexed by SpellID or ClassTreeSkill for its bound. A previous audit found a real bug here: every skill with id 64 or above was stuck at rank 0.
- **Tooltip against mechanic.** The rule is that each skill's hover text states the numbers the game actually applies, at this rank and the next. `oracool_skill_rules_test` checks the tooltip text. Look for mechanics that read a different formula, rank, or source than the text does.
- **Rage (Barbarian).** The Barbarian has no mana. He may only pay for skills through `CanPaySkill`/`SettleSkill`. Find any path that charges mana or rage twice or not at all.
- **Monster-state leaks.** Look for curses, auras, and ground effects that leave state on a monster after it dies or its slot is reused.

### 3. Items, loot, and crafting

Files: `items.cpp` (the Oracool parts), `oracool/smart_loot`, `treasure_class`, `item_tiers`, `item_names`, `unique_affixes`, `lesser_uniques`, `item_sets`, `runewords`, `crafting`, `imbuement`, `salvage`, `signets`, `gems`, `charms`, `essence`, `level_requirement`, `encounter_items`, `necro_items`, `stat_sheet`.

Invariants to test against the code:

- **Affix level.** An affix's level is never above the item's level.
- **One affix list.** Since v1.12.182 there is a single affix list, `_iOracoolAffixes`. The old prefix and suffix split should no longer shape the result anywhere.
- **Rebuilding a saved item.** An item rebuilt from its seed must come out identical to the one that dropped.
- **One path for fresh drops.** Every fresh drop goes through one funnel (`FinishOracoolDrop` / `FinalizeFreshDrop`).
- **Crafting.** Crafting, the cube, and salvage never destroy their inputs unless the output is placed.
- **Rift guardians.** Since v1.12.187 they drop random items, not their scripted unique.
- **Stash sort.** Re-verify STASH-01 from the last audit: sorting must never drop an item that no longer fits.

### 4. World: rifts, levels, monsters

Files: `oracool/rift`, `stonegate`, `stonegate_menu`, `zone_registry`, `area_level`, `stairless`, `waypoint_menu`, `monster_variants`, `monster_difficulty`, `monster_scale`, `named_encounters`, `endgame_boss`, `quest_marks`, and `monster.cpp` / `interfac.cpp` where they call these.

- **Generated rift levels.** Check the kill bar and the guardian spawn. Check entry and exit, including a portal back to town. The rift panel should show while a rift is open, and be gone once it is closed.
- **Changing level.** Check travel through stairs, waypoints, town portals, and the Stonegate. Check which loading screen each one picks.

### 5. Interface and drawing

Files: the 32-bit renderer path, `oracool/sprite_mix` (it keeps a disk cache keyed by `CacheVersion`), `sprite_colours`, `hero_look`, `hero_preview`, `ornate_border`, `cursor_tooltip`, `hud_*`, `shop_grid`, `shop_tabs`, `workshop`, `wirt_cart`, `levski_*`, `crafting_menu`, `window_close`, `inventory_layout`, `socket_overlay`.

- **Click-through.** A click on an open window must never reach the world or the window behind it.
- **Hover against click.** Hover and click must resolve to the same cell or button.
- **Drawing bounds.** Nothing may draw outside the surface, and the maths must stay in range at every supported resolution.
- **Cache.** Check whether the sprite disk cache can serve stale colours after a code change that should have bumped `CacheVersion`.

### 6. Build, assets, and tests

Files: `CMakeLists.txt`, `tools/oracool_mpq_pack.js` (the node MPQ writer, since v1.12.185), `tools/oracool_mpq_pack.cpp`, the missile art census in `misdat`, `skill_sounds`, and `test/oracool_*`.

- **The two packers.** Does the node packer produce an archive the engine's MPQ reader accepts in every case? Consider an empty file, a file of exactly one sector, a file at the 4096-byte sector boundary, a 2048-entry table near full, and a hash collision chain.
- **Stale archive.** Can a build finish with an `oracool.mpq` that does not match the asset folder?
- **Missing art.** Missing art must fail softly: the effect draws nothing, and nothing crashes.
- **Test isolation.** Look for tests that share globals, archives, or save folders. Look for tests that pass only in their written order.

## Deliberate design (do not report these as bugs)

- Single-player only. The multiplayer screens exist but are unsupported, so do not audit network play.
- Every hero starts a New Game. There is no Continue.
- An item file must match the current `OracoolItemFormatVersion` exactly. Other versions are rejected on purpose, and we bump the version rather than keep an old layout.
- Spells never miss monsters (`SpellsNeverMiss`, player.h). This is a D2-style trial.
- Floors 17-24 (Hive and Crypt) are weaker and give less XP on purpose.
- The belt takes only potions. Shards, signets, and sealed maps drop but are never sold.
- The Barbarian has no mana.
- 32 skill rows are inert by design until future engine systems land. The audit test lists them.
- The Blizzard game archives (`diabdat.mpq`, `hellfire.mpq`, `hf*.mpq`) are never distributed. Only `oracool.mpq` and `devilutionx.mpq` ship.
- **Test binaries blocked by Windows.** Windows Smart App Control may block a freshly linked test binary, with exit 4551 or `_NOT_BUILT` in ctest. That is the machine's security policy, not a code bug. Deleting the exe and relinking it usually clears it.

## Rules for the audit

- **Read-only.** Do not edit code, assets, or save files. Do not commit or push. Running the existing tests is fine.
- **Evidence for every finding:**
  - `file:line` at the commit above.
  - Confidence: *confirmed* (traced end to end), *likely*, or *speculative*.
  - The concrete inputs or state that trigger it.
  - A suggested fix.
  - A regression test that fails today.
- **Say how you know.** State whether a finding comes from reading the code, from a model or simulation, or from running a test. Do not claim you reproduced something in gameplay unless you did.
- **Precision over count.** Five confirmed findings beat thirty guesses. If a track is clean, say so and list what you checked.
- **Earlier findings.** The v1.9.304 findings were fixed in v1.9.305-311, and the v1.11.102 findings in v1.11.103-106. Report one again only if it has regressed.

## Priorities

- **P1:** crash, corrupted or lost save, or lost items.
- **P2:** wrong gameplay, a broken promise in a tooltip, or a mechanic that silently does nothing.
- **P3:** inconsistency, dead code with risk, or a gap in the tests.
- **P4:** cosmetic.
