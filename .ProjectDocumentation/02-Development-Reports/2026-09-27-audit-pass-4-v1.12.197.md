# 2026-09-27 - Audit pass 4: the hero sheet, stale vanilla sizes, the item UI, and state that outlives the game (v1.12.197)

**Date:** 2026-09-27 - Debug only. The user: "check my dev notes and process, then make a number of audits. i am going to bed."
The two dev notes went out as v1.12.196 (see its report). Then four read-only audits ran in parallel, one on each of:
- the hero sheet (v1.12.194-196);
- literals still holding a vanilla size the fork has outgrown;
- the item UI work of v1.12.189-193;

The PC slept from 03:17 to 09:04 and the first four agents stalled, so they were run again. I checked every finding in the code before fixing it. The fixes below are ranked by severity; findings left alone for a decision are at the end.

## CRASH / memory corruption

- **The item format stayed at 13 after a v13 file loaded** (loadsave.cpp):
  - `AcceptItemFormat` is set by three loaders: hero items, the stash and the extra tabs. Nothing set it back.
  - After one v13 file, every later load read each item 4 bytes short and walked the rest of the file as garbage: levels, dropped items, premium stock. Those files are all written today, with `_iPLCR`.
  - A scope guard (`ItemFormatScope`) in each of the three loaders now puts it back to 14 on every return path.
  - Verified by reading; there is no test. Building a v13 stash file inside a test needs a writer for the old format.
- **Using an item from backpack pages 2-10 removed page 1's item** (inv.cpp `UseInvItem`):
  - The keystone, sealed map, Hive and Grave branches called `Player::RemoveInvItem`, which always works on page 1.
  - A keystone used from page 3 opened the rift, deleted page 1's item at the same index, and stayed to open rifts again.
  - With page 1 empty, the count went to -1 and the next pickup wrote `InvList[-1]`.
  - Fixed with `ConsumeUsedBackpackItem`, which removes from the page the item is on. Test: `InvTest.ConsumeUsedBackpackItem_TakesTheItemFromTheOpenPage`.
- **The controller crashed on the bottom-right backpack cell** (plrctrls.cpp `FindFirstSlotOnItem`):
  - The loop stopped one short (`<` against an inclusive last), so an item alone in cell 70 was never found. The -1 then indexed `InvRect[-1]`.
  - This is more likely since v1.12.196: the tenth pickup onto the bottom row lands there.
- **The `setspells` debug command never returned** (debug.cpp): a `uint8_t` counter against `MAX_SPELLS` = 290 wraps before it gets there.

## HIGH

- **Taking Vitality back could kill the hero** (player.cpp `RefundStatPoints`):
  - Current life goes down with it, and at 0 the hero dies.
  - The refund now stops one point of life short; the rest stays spent, to take back later. Test: `Player.RefundStatPoints_VitalityNeverTakesTheLastPointOfLife`.
- **RESET could make points**:
  - It returned every spent point, although `ModifyPlr*` stops at a base of 0; a curse below what was spent made the difference.
  - It now goes stat by stat through `RefundStatPoints`, which also brings the Vitality floor to the list sheet's RESET. Test: `Player.ResetPlayerStats_NeverReturnsMoreThanTheBaseHolds`.
- **Controller: the six added worn slots could not be reached** (plrctrls.cpp):
  - Shoulders, bracers, gloves, waist, legs and boots had no D-pad path, no cursor coordinate and no place in "nearest slot".
  - They are in all three now. Where vanilla's hand-written moves go nowhere, the D-pad takes the nearest worn slot in that direction (by the slots' rects), or goes down into the backpack's top row.
  - A held item of one of the six types goes to its slot.
- **Controller: stash rows 11-16 could not be reached**:
  - Seven literals assumed vanilla's 10x10 stash page. The page is 10x16.
  - They now use `StashGridColumns`/`StashGridRows`.
- **Controller: pages 2-10 snapped to page 1's items**: the cell and item reads now go through the page on screen.

## MEDIUM

- **The Mendicant Shrine took half the gold for nothing at level 99**, and past 70 it gave only a fraction.
  - It now charges exactly the gold that became experience. Test: `InvTest.MendicantShrine_ChargesOnlyForExperienceGained`.
- **Store lists held 48 items, vanilla's backpack plus belt**:
  - The sell list stopped filling there *before* sorting by price, so anything past the 48th sellable item never showed, including later pages.
  - `StoreHoldCapacity` now counts the backpack, belt, nine pages and worn slots. Repair-all's guard and Cain's page walk use it too. Test: `StoresTest.SmithSell_ListsEverySellableItemPastVanillasFortyEight`.
- **Cain could not see unidentified gear in the six added worn slots**:
  - His list is now a table over all 13 slots, like the repair list. The decoder reads the same table.
  - Test: `StoresTest.StorytellerIdentify_ListsAndIdentifiesAPieceWornInAnAddedSlot`.
- **A new hero met the last hero's Wirt**: `InitStores` left both of his grids, which restock only on a higher tier. Test: `StoresTest.InitStores_EmptiesWirtsShopAndGambleGrids`.
- **The Rift Monument's object ids matched objects on dungeon floors**:
  - The ids were kept after town, and a floor gives the same `Objects` slot to a door or barrel. That object then drew in the floor pass, under the heroes.
  - Both checks are now town-only.
- **Some combat state was cleared only in `InitMonsters`, which town never runs**, and a New Game starts in town. The next hero could start with:
  - the last hero's half-speed chill;
  - an RfA-12 field (a Bone Storm) still circling slot 0;
  - passive clocks and warcry wards.

  The five clears moved to `InitLevelMonsters`, which every level load passes.
- **A companion's arrows moved the hero's To hit bar**: they fly with the hero as their source, and they are skipped now.
- **Refinement shards scaled every resistance but cold**: one missing line.

## Not changed: decisions for the user

- **Workshop reroll price and affix lock reset when you go back to the menu** (HIGH as an exploit):
  - They are per game by design ("honest until the format is bumped for other reasons"), keyed by item seed.
  - Since a New Game keeps the hero and their items, quitting resets the doubling price and frees the locked affix.
  - To keep them, they could go in a hero-file chunk keyed by seed (no item format bump) or on the item (format 15).
- **A Guardian Keystone is spent when the rift opens**, and the rift lives one game. Quitting inside the 15 minutes loses it. D3 does the same; the alternative is to spend it on entry or on the guardian's death.
- **The Armor class odds leave out block and dodge**: the bar is the chance a blow lands before the block roll. The wording or the maths could change.
- **The tooltip card sorts lines by English prefixes**: in another language every line lands in the body, and nothing is lost.
- **A tall card is clipped at the bottom** of a short screen. It cannot crash.
- **The telemetry session id is one per process**, so two heroes in one run merge in the balance CSV.
- **The grouped sheet blocks stat points in multiplayer**. V1 is single player.
