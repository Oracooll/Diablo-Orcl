# Jewels say what they do

**Version:** 1.11.073
**Date:** 2026-09-12
**Branch:** renderer-32bit

## What was asked

> "jelews have no description in their pop-up. add appropriate description."

## Nothing had to be written

The description already existed and was never asked for. `items.cpp`'s panel builder gates the
per-host socketable lines on:

```cpp
if (IsOracoolGemIdx(item.IDidx) || IsOracoolRuneIdx(item.IDidx))
```

Jewels are not in it, and they had no branch anywhere else in the function either - gems and runes
share this one, Mystic Orbs have their own just above, charms go through `CharmEffectLine`. A jewel
was the only socketable family with nothing, so its panel showed a name, a quality level and no
reason to pick it up.

The fifteen jewels are **ordinary `Gems[]` rows** (`jewels_effects.inc`, generated by
`tools/GenJewels.ps1`) carrying real per-host numbers - `armorToHit`, `shieldBonusAc`,
`weaponDamageMod` and so on. And `ResolveGem` ends in `return FindGemRow(idx)` for any index that is
not a gem type/quality pair, so it resolves a jewel at 100%. `GemHostEffectLine` has therefore always
produced the right three lines for a jewel; the gate was the one place that never called it.

So the fix is that gate plus `IsOracoolJewelIdx`. `items.h:595` already listed all four socketable
families as the canonical set - gems, runes, jewels, orbs - which is what says this gate had drifted
rather than that jewels were meant to be silent.

A Flawed Jewel of Fervor (`armorToHit 9`, `shieldBonusAc 6`, `weaponToHit 9`) now prints one line per
host instead of none, and empty hosts still fall away as they do for gems.

## Verification

Debug and Release build clean; **718/718** tests pass. RTM updated.

What only the game can show is the wording in place - the three lines are generated by the same
function gems and runes already use, so they are formatted and coloured identically, but whether a
jewel's numbers read well at three lines is worth a look.
