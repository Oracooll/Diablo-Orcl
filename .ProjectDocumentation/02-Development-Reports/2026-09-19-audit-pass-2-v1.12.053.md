# Second audit pass: shards, saves, Necromancer, companions (v1.12.053)

**Date:** 2026-09-19 - Debug only - **819 of 819 tests** (one run, build 22; the Zod test and the flipped set-level expectation included). User: "Do a bunch more audits." Four read-only
audits on the areas the first pass had not touched; every finding re-read in the code before the fix. Nothing
seen in play.

## Imbuement Shards

| # | Finding | Fix |
|---|---|---|
| 1 | **Tempering disarmed a Zod-socketed item.** Zod marks indestructibility in `_iDurability == 255` alone (so extraction can put the item back); Tempering tested `_iMaxDur` only and added ten: a destructible 265 with the rune still listed. Same hole on restore after a rebuild and on Cleanse (which clamped 255 to the max) | `CanReceiveShardKind` refuses when either sentinel is set; `RestoreImbuements` leaves `_iDurability` alone at 255; `StripImbuements` does not clamp the sentinel. Test extended (Zod refused; Cleanse keeps the sentinel) |
| 2 | Refinement rounded any affix under 17 to zero at 3% while its line promised "every affix" | at least one point whenever there is anything to scale |
| 3 | per-kind limits held only at apply time; a foreign record with twenty Arcana was twenty spell levels | counted per kind on load, entries past `ShardLimit` dropped |
| 4 | the ledger's array was a bare `20` | `MaxImbuementKinds`, static-asserted equal to `Item::MaxOracoolImbuements` |

Clean: ledger integrity, plain-member copy everywhere, provider runs once, Ease used by all three requirement
paths, shards out of pools and off the belt, UI apply path.

## Saves and loaders

| # | Finding | Fix |
|---|---|---|
| 1 | **One hero from an older item format bricked the character-select screen for every slot**: `LoadHeroItems` called `app_fatal` on a version mismatch, and the hero list calls it for every slot | it returns false; the real load path (`pfile_read_player_from_save`) stops with the message, the preview lists the hero without gear |
| 2 | `heroitems` had no length check: a truncated file read as zero-filled phantom items | the fixed-size record's exact length is required |
| 3 | `_iUid`, `_iSpell`, `_iPrePower`/`_iSufPower` unbounded on load in Hellfire mode; they index tables directly | `RemoveInvalidItem` drops a record past any of them |
| 4 | Levski's grid is an unsaved container and autosave did not exclude it: a crash with items in the grid lost them | `IsSafeToSave` requires the window closed |
| 5 | a dead `StashVersion == 5` branch | removed; exact match only |

Clean: writer/reader byte symmetry (103 extension bytes, `OracoolItemExtensionSaveSize` matches), all three item
carriers on format 11, the chunk tail's framing, every other bound, the atomic save transaction, telemetry.

## Necromancer

| # | Finding | Fix |
|---|---|---|
| 1 | **A skeletal mage's bolt kill credited nobody**: the minion-fired missile went through `MonsterTrapHit`, which runs `MonsterDeath` itself; no one was tagged, so no XP, no Life Tap, no on-blow effects | the target is tagged with the owner before the hit; `MonsterTrapHit` reports the damage dealt and Life Tap / the army's on-blow effects fire after, as the melee seam does |
| 2 | **Raise and Revive ate the corpse before knowing a body could stand**: corpse taken, haste granted, effect played, then `SummonMinion` could refuse (floor at its type limit, no tile) | Raise checks a corpse is near and the skeleton type can be added first; both raise the body first and grant the haste and play the effect only on success |
| 3 | Weaken's debuff and Decrepify's chill outlived the curse (laid with the curse's clock; `Release` undid only Confuse) - an Eternal Torment Decrepify replaced by Doom stayed slowed for good | `Release` clears the warcry debuff for both and the chill for Decrepify (`ClearChill`, new) |
| 4 | Army of the Dead's remaining pulses landed on the next floor at the same coordinates | its state is cleared on level load beside the minion records |
| 5 | Bone Prison cut whatever monster occupied the prisoner's slot, even a fresh spawn after its death | the prisoner must be on the prison's tile |
| 6 | misleading indentation in two kill seams (missiles.cpp Life Tap line, monster.cpp Rfa12 kill line) sat outside their `if` | braced |

Clean: golem slots untouched by the army, minion/corpse/curse lifetimes, Essence, the pay path, all 72 rows
reach a case, item ranges, Bard bases stay hidden.

## Companions

|---|---|---|
| 1 | **`LevelHasGolemSlots` refused set levels** (the Skeleton King's lair, the Chamber of Bone, Lazarus): the v1.12.012 note read `InitGolems` alone, but `SetMapMonsters` adds the golem type and four bodies on every set level. Companions and the Golem spell were kept out for nothing | `leveltype != DTYPE_TOWN`; the test's set-level expectation flipped; the memory note corrected |

Clean: slot allocation and eviction, level-change sweep, expiry path, attribution (companion kills credit the
owner; loot never for the companion), no variant on a golem body, HUD reads.
